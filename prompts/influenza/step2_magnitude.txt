For EACH of the next {horizon_len} periods:
  • If Step 1 said "no change", the size is "none" — keep the baseline; do NOT invent a move.
  • If Step 1 said "increase" or "decrease", choose exactly ONE size class for HOW BIG the
    revision is, in that already-chosen direction. The size classes are PROPORTIONAL — each
    describes the revision as a PERCENTAGE of that period's baseline forecast value:

{bin_definitions}

The size classes are UNSIGNED — they describe the magnitude of the move as a fraction of
the baseline only; the Step-1 direction supplies the sign (up/down). A larger class means a
proportionally bigger move away from the baseline. Because the classes are relative, the
same class means a bigger absolute change when the baseline value is high than when it is
low — always think in percent-of-baseline terms. The class ranges are deliberately UNEQUAL
in width: they were set so that, historically, about the same share of actual moving
revisions fell in each class — so no class is intrinsically rare, and a wide top class does
not mean extreme moves are unlikely.

How to size each period:
  • Tie the size to how STRONG and FAST the move is in the report text: a "sharp", "rapid",
    or multi-period accelerating change supports a LARGER class; "plateauing", "slowing", or
    "stabilizing" supports a SMALLER class.
  • Cross-check the recent baseline errors (item 3), MATCHING THE HORIZON (near-horizon errors
    for the near periods, far-horizon errors for the far period). The errors are already
    percentages of the forecast — the same scale as the size classes: if the relevant-horizon
    forecast has recently been off by a large percentage in this direction, a larger class is
    plausible; if only off by a few percent, a smaller class.
  • Reason each period on its own — sizes usually differ.
  • Be conservative when uncertain: if the evidence does not clearly support a big move, pick
    the smaller class.
